# SafeVault 项目问题总结

更新时间：2026-09-21

## 当前状态

- `npm test`：通过。
- `npm run build`：通过。
- `npx tsc --noEmit`：未通过，存在未使用导入、缺失类型导出以及 Web Crypto `BufferSource` 类型错误。
- `npm audit`：当前 npm 镜像不支持审计接口，未能得到依赖漏洞结论。

## 高优先级问题

1. **同步认证缺少服务端限流**
   - 服务端直接保存并比对客户端生成的 `authHash`。
   - `authHash` 泄露后可被重放登录，服务端没有按账号/IP 的登录失败限流。

2. **默认同步链路为明文 HTTP**
   - Docker 直接暴露 `8088` 端口，Node 服务本身未提供 TLS。
   - 不应将该端口直接映射到公网；远程访问应通过 HTTPS 反向代理或 VPN。

3. **密文外层字段没有完整性认证**
   - AES-GCM 只保护敏感 payload。
   - 标题、网址、分类、标签、删除状态等外层字段可以被篡改而不触发解密失败。

4. **备份文件不是整体加密包**
   - 条目敏感 payload 已加密，但标题、网址、分类和金库元数据仍以 JSON 外壳形式存在。
   - 与 SPEC 中“备份文件整体加密”的要求不一致。

5. **关键配置变更不会同步到 NAS**
   - 修改主密码、二级密码、锁屏时长以及恢复备份后，当前代码只更新本地存储。
   - 其他设备可能继续使用 NAS 上的旧金库版本或旧安全配置。

6. **永久删除缺少删除墓碑**
   - 双向合并会保留本地独有条目。
   - 某台设备永久删除的条目如果仍存在于远端，后续同步可能重新出现。

## 中优先级问题

7. **TypeScript 严格检查未通过**
   - 存在未使用导入。
   - `VaultItem` 类型未导出。
   - `DecryptedVaultItem` 在存储层缺少导入。
   - Web Crypto API 的 `Uint8Array<ArrayBufferLike>` 类型与当前 DOM 类型定义不兼容。

8. **剪贴板清理可能覆盖用户的新内容**
   - 定时器到期后直接写入空字符串，没有确认剪贴板内容仍是 SafeVault 刚复制的内容。

9. **运行时测试数据不应进入版本库**
   - `data/` 下的运行数据库可能包含认证摘要、Session Token 或用户密文。
   - 已加入 `.gitignore`，提交时应确保这类文件不进入 Git 历史。

## 建议修复顺序

1. 先补 HTTPS、服务端限流和安全的认证协议。
2. 设计配置版本与删除墓碑，修复多端同步一致性。
3. 使用 AAD 或整体加密保护条目外层字段，并重做整体加密备份格式。
4. 修复 TypeScript 检查错误，加入同步冲突、外层字段篡改和删除传播测试。
5. 最后处理剪贴板清理和交互层细节。
