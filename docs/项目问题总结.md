# SafeVault 项目问题总结

更新时间：2026-10-03

## 当前状态

- `npm test`：通过，包含 v2/v3 密钥包裹、整条记录加密和同步协议回归测试。
- `npm run build`：通过。
- `npx tsc --noEmit`：通过。
- `npm audit`：当前 npm 镜像不支持审计接口，未能得到依赖漏洞结论。

## 安全边界与剩余事项

1. **同步认证摘要仍是高价值凭证**
   - 当前已加入一次性挑战、HMAC 响应、账号/IP 失败限流和 HttpOnly Cookie。
   - 客户端仍为兼容 Android/iOS/Electron 保存 Bearer 会话；生产环境必须使用 HTTPS，并应把 NAS 端口限制在反代/VPN 内。

2. **默认开发链路仍允许局域网 HTTP**
   - 基础 Compose 为方便首次部署保留局域网 HTTP；生产 HTTPS 组合会启用 `REQUIRE_HTTPS=true` 和可信反代校验。
   - `8088` 不得直接映射到公网，远程访问必须通过 HTTPS 反向代理、Cloudflare Tunnel 或 VPN。

3. **历史 v1/v2 数据可能存在明文外壳**
   - 新 v3 已将标题、网址、分类、标签、删除状态、时间戳等全部放入 AES-GCM 密文，并用条目标识 AAD 绑定。
   - 旧数据只能在读取后逐步迁移；旧备份应在确认新备份可用后删除。

4. **旧版明文备份仅作为迁移输入**
   - 新版导出使用整体 AES-GCM 密文备份并绑定备份协议 AAD。
   - 旧版明文外壳备份导入后应立即重新导出加密备份并删除原文件。

5. **非核心显示配置仍以设备为范围**
   - 主密码和全库密文已通过原子改密接口一起同步；锁屏时长属于设备本地安全策略，不应被另一台设备远程覆盖。

6. **永久删除缺少删除墓碑**
   - 双向合并会保留本地独有条目。
   - 某台设备永久删除的条目如果仍存在于远端，后续同步可能重新出现。

## 中优先级问题

7. **TypeScript 严格检查已修复**
   - 当前 `npx tsc --noEmit` 已通过；后续改动仍需保留该检查。

8. **剪贴板清理可能覆盖用户的新内容**
   - 定时器到期后直接写入空字符串，没有确认剪贴板内容仍是 SafeVault 刚复制的内容。

9. **运行时测试数据不得进入版本库**
   - `data/` 下的运行数据库可能包含认证摘要、Session Token 或用户密文。
   - 已删除原测试数据库，并更新 `.gitignore` 禁止确定性测试库和运行库进入 Git。

## 后续安全工作

1. 将浏览器端 Bearer 会话迁移到 HttpOnly Cookie，并将原生端会话放入 Android Keystore / iOS Keychain，减少 localStorage 暴露面。
2. 为同步删除引入经过认证的 tombstone/版本向量，避免多设备删除后被旧设备重新带回。
3. 在受控环境中增加依赖漏洞扫描、SAST、DAST 和容器镜像签名验证。
4. 对生产 NAS 做端口白名单、系统更新、独立备份离线演练和恢复演练。
