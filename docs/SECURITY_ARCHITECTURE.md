# SafeVault 安全架构与部署基线

更新时间：2026-10-03  
适用版本：1.3.1

## 结论先行

SafeVault 的服务端/NAS 只保存同步认证材料、金库元数据和客户端密文；主密码、金库明文和解密后的条目不会发送到服务器。新协议中，主密码不直接作为条目加密密钥，而是通过 PBKDF2-SHA256 派生不可导出的 KEK，用 KEK 解包本地随机生成的 256 位金库数据密钥（DEK）。忘记主密码且没有仍处于解锁状态的可信设备时，没有服务器重置、找回、万能密钥或管理员绕过路径，数据不可解密。

“绝对没有漏洞”不是任何软件可以诚实提供的保证。这里采用浏览器原生 Web Crypto、AES-GCM 认证加密、版本锁、失败限流、HTTPS 反代、安全响应头、输入大小/结构校验和可回滚灾备，并通过自动化测试持续验证安全边界；生产环境仍应使用强主密码、及时更新、最小暴露面和独立备份。

## 密钥与数据协议

1. 首次初始化生成 16 字节随机盐和 32 字节随机 DEK。
2. 主密码经 PBKDF2-SHA256 600,000 轮派生 256 位 KEK。旧数据最低按 100,000 轮兼容读取，旧账号认证摘要按记录中的轮数兼容，新增/升级账号使用 600,000 轮。
3. DEK 使用 AES-GCM-256、独立 12 字节随机 IV 和固定 AAD `SafeVault:VaultKey:Wrap:v2` 包裹后写入 `VaultMeta`。KEK/DEK 均以不可导出 `CryptoKey` 形式使用。
4. 新版条目使用 v3：标题、分类、网址、账号、密码、备注、标签、收藏、删除状态、时间戳、TOTP、自定义字段和密码历史全部进入同一 AES-GCM 密文。服务器仅可见随机条目标识、IV、版本和 Base64 密文。
5. v3 AAD 绑定随机条目标识。条目标识、IV、密文或元数据包裹字段被篡改时，解密失败；客户端批量解密采取 fail-closed，不允许把“无法验证的条目”当成缺失数据继续合并。
6. 旧 v1/v2 数据只用于兼容读取；下一次编辑、导入或改主密码时会重新写成新协议。旧格式的明文外壳不能追溯擦除，完成迁移后应删除旧备份。

## 忘记主密码时的不可恢复边界

- 服务端没有 `/reset-password`、密钥托管、恢复邮箱解密、管理员解密或明文密码字段。
- 修改主密码必须先用当前密码解锁，客户端在本地重新生成密钥材料并重新加密全库，然后才更新同步认证摘要。
- 加密备份也必须使用主密码解密；忘记密码时，备份只能保留，不能被服务器或开发者打开。
- 若仍有一台可信设备处于解锁状态，应立即导出加密备份并在确认新密码后完成改密；若所有设备都锁定且密码遗失，数据视为密码学上不可恢复。

## 服务器/NAS 部署基线

生产环境应使用 `docker-compose.yml` 与 `docker-compose.https.yml` 组合启动，并将公网入口交给 Caddy、Cloudflare Tunnel 或其他可信 HTTPS 反向代理：

```powershell
docker compose -f deploy/docker-compose.yml -f deploy/docker-compose.https.yml up -d --build
```

生产组合会启用：

- `REQUIRE_HTTPS=true`：应用拒绝绕过反代的明文请求；
- `TRUST_PROXY=true`：只在明确部署了可信反代时信任 `X-Forwarded-Proto`；
- 仅允许正式 HTTPS 域名的 CORS 来源；
- HSTS、CSP、`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`；
- 默认 10 MiB JSON 请求上限、最多 10,000 条同步条目和 Base64/版本/字段结构校验；
- 账号/IP 登录失败限流、一次性 60 秒挑战和版本乐观锁；
- 改主密码使用 `/api/auth/change-password` 原子提交：认证摘要、新金库密文、版本号和改密前快照一起切换，不使用不安全的“两阶段半提交”；
- 主数据库与独立灾备目录的原子写入和历史快照。

不要把 Node 服务的 HTTP 端口直接暴露到公网，不要打开 DMZ，也不要把 NAS 管理后台端口映射到公网。路由器端口映射只应指向 HTTPS 反代；若使用 Cloudflare Tunnel，优先保持入站端口关闭。

## 已知边界与运维要求

- PBKDF2 是当前 Web Crypto 的跨平台兼容基线；实际安全性仍高度依赖主密码熵值。不要使用截图中的简单口令或在多个服务复用密码。
- 浏览器版同步配置仍需兼容 Android/iOS/Electron 的 Bearer 会话，因此会保存会话凭证。部署时必须使用 HTTPS；若未来只面向浏览器，可进一步收紧为仅 HttpOnly Cookie，并迁移原生端到系统安全存储。
- 服务端拥有“拒绝/删除/替换密文”的能力，但没有读取密文的能力；因此版本锁和独立回滚备份用于防误覆盖，不等于防勒索或防 NAS 主机被完全控制。
- CSV 导出是明文高风险操作，只应在可信设备上短暂使用，导出后立即删除并清空回收站。
- 每次发布前执行 `npx tsc --noEmit`、`npm run build`、`npm test`，并检查 `git status`，确认 `data/`、会话数据、签名密钥和部署令牌没有进入版本库。

## 安全回归测试覆盖

`tests/test-security-boundary.js` 验证：v3 外壳不泄露元数据、正确密码能够解包 DEK、错误密码无法恢复 DEK、AES-GCM 密文篡改失败、条目标识篡改失败。`tests/test-sync-protocol.js` 验证一次性挑战、会话 Cookie、认证摘要更新、版本锁和同步协议回归。
